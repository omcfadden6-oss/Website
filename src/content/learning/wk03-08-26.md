## Goals for the week
I want to make a start on my first project - I would like to first do a qualifying analysis, so that I am comfortable analysing and comparing one-lap pace, and then a race analysis. I'm not sure what race I plan to analyse yet, but I know I would like to analyse Monaco qualifying, because I feel like that has been the most exciting qualifying session of the year - I know I enjoyed watching it.

I mainly want to find my footing with FastF1 - figure out what I can and can't get from it, and just play around with the different plots I can make - that way I can decide what will be most useful for analysing the Monaco qualifying session.

## What I worked on
- **Built my project workspace set-up** - I set up Virtual Studio Code as my work space, that way I can work on all different types of files, and have everything in the one place. It was tedious, and yielded many errors, but I know it will 100% pay off in the long term. Setting this up really was a perfect example of "mistakes allow you to learn" - because dealing with my various errors in set up forced me to learn more about the setup itself, and I feel like having a better understanding of how it all works has made me better at troubleshooting and finding the source of errors.

- **Set up a virtual environment in my FastF1 projects folder** - this is where all the various Python packages I have to import will live (eg FastF1) - this is what yielded the most errors, mainly through me being careless about file locations etc. I have definitely learned my lesson that hard way to pay more attention to these little details.

- **Started my first analysis project** - began analysing Monaco qualifying in FastF1 on Python. I started initally just playing around with FastF1, finding my feet on everything that I can do and making a few basic telemetry plots - speed/distance, gear/distance, gear map etc. I want to make sure I actually understand what is going on, and what I am analysing, and I found it really beneficial to take that time initially to just play around with things and understand how it all works.

- **Created my `tools` package in Python** - this is what I am most proud of this week. I set up an installable Python package containing my most used functions for analysis - that way I can simply import the package and run the function, rather than having to rewrite it in every project.

## My main takeaway from the week
I have already touched on this, but my main takeaway from this week has certainly been that mistakes allow you to learn. Getting everything set-up and starting out with FastF1 brought many errors, but fixing them gave me a much better understanding of how it all works, and I feel much better equipped to deal with future errors. I will admit that progress does feel slow, but I am going to allow myself that while I am starting out, and I feel like taking my time at this stage to make sure I understand what I doing will certainly pay off in the long run.

I really did enjoy getting to grips with FastF1 - I think it's just so fascinating to be able to work with real data from F1 sessions this year. It has been great to brush up on my Python skills as well, which were certainly a little rusty, as it has been a few months since my last lab project at uni!
